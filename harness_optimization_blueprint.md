# Harness Configuration & Workflow Optimizations for Claude Code

## Purpose
This document establishes the production-level optimizations designed to transform our current **12-stage sequential workflow** into a high-velocity, token-efficient, and highly automated AI-assisted engine. 

These recommendations address architectural bottlenecks inherent to long-running, multi-gated interactions with a CLI agent like **Claude Code**. The core objective is to maximize the utility of **Anthropic's Prompt Caching**, drastically reduce execution latency, minimize conversational friction, and maintain the precise safety guarantees established in the repository's original design.

---

## 1. Architectural Cache Isolation Strategy

### Context Index Optimization (`AI_CONTEXT.md`)
To prevent high-frequency file mutations from repeatedly invalidating the server-side prompt cache, the repository context layout must be segregated by volatility.

```markdown
<!-- CACHE BLOCK: STATIC (Read once per session) -->
<!-- These files remain pinned in Anthropic's cache, saving ~90% in token costs -->
- [Architecture Guidelines](Harness_Config/Context/Architecture_Design.md)
- [Working Agreements](Harness_Config/Context/Working_Agreements.md)
- [UI Guidelines](Harness_Config/Context/UI_Guidelines.md)
- [Decisions & Consistency](Harness_Config/Context/Decisions_Consistency.md)

<!-- EPHEMERAL BLOCK: VOLATILE (Read only on-demand at specific gates) -->
<!-- Isolated payload shifts so mutations don't flush the static cache -->
- [Current Session State](Harness_Config/Context/Current_Focus.md)
- [Running Stale List](.claude/scratchpad/stale-docs.md)
```

### Why this is Valid & Contributes to the Goal
* **Prevents Cache-Thrashing:** When a file changes, everything following it in the prompt must be re-cached. Isolating highly dynamic elements like `stale-docs.md` and `Current_Focus.md` ensures that heavy, immutable architectural code rules stay warm in the server cache indefinitely.
* **Granular Chunking over Complete Reads:** Structuring files with clear block attributes allows Claude to scan targeted boundaries using native terminal parsing utilities (like `sed` or `awk`), bypassing massive context window file-reads entirely.

## 2. Compressed Production Workflow Pipeline

The original 12-stage workflow provides excellent safety but contains **7 distinct manual approval gates**, causing heavy latency. This optimized pipeline condenses execution into **4 high-speed blocks** by shifting gates from *conversational interaction* to *automated terminal execution*.

```
[ BLOCK A: SCOPE ] ──► [  BLOCK B: FAST-LOOP CODE  ] ──► [ BLOCK C: ASYNC REVIEW ] ──► [ BLOCK D: FLUSH ]
 (Single Gate) 🔒       (Autonomous Test & Fix)         (Red-Team & Historian) 🔒     (Automated Sync)
```

### Block A: Integrated Scoping & Gating (Compresses Stages 1, 2, 3, & 4)
* **The Optimization:** Merge Information Gathering, Open Questions, Sub-phase Layouts, and Implementation Planning into a single comprehensive scoping brief generated by the main session.
* **Why it Contributes:** Eliminates three separate, sequential conversational blocks. For standard issues, you check the overall scope **once** rather than halting execution at three separate plan milestones.

### Block B: Autonomous Fast-Loop Execution (Compresses Stages 5 & 6)
* **The Optimization:** Grant Claude Code complete autonomy to step through all defined sub-phases sequentially without halting to check in. The agent must use a test-driven local loop.
* **Execution Rule:** For each sub-phase, Claude must write code and immediately execute terminal test commands (`npm test`, `dotnet test`, etc.). The agent auto-corrects compiler errors, syntactical bugs, and broken test assertions out-of-sight.
* **Why it Contributes:** Shifts the error-correction mechanism from reactive (discovered during human or trailing subagent review) to proactive (handled instantly by code execution state).

### Block C: Concurrent Verification Sweep (Compresses Stages 7, 8, 9, & 10)
* **The Optimization:** Once a Pull Request is automatically generated, the main session triggers the `red-team` subagent and the `historian` documentation pass **simultaneously** rather than sequentially.
* **The Payload:** Claude delivers a single unified package: the functional code diff, the Red-Team's scored logic vulnerabilities, and the Historian's final documentation diff.
* **Why it Contributes:** Drastically reduces total turn clock-time. It groups all trailing analytical feedback loops into a single multi-file human review gate.

### Block D: Automated State Sync & Cleanup (Compresses Stages 11 & 12)
* **The Optimization:** Transition the Memory Flush from a manual text-audit session to an automated cleanup routine triggered upon PR merge.
* **Why it Contributes:** Removes the clunky interaction of manually specifying which scratch files to delete, condense, or keep. A programmatic wrapper can strip the temporary `.claude/scratchpad/` paths and cleanly reset the repository state for the next issue.
